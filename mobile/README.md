# واثق — تطبيق الموبايل

تطبيق React Native / Expo SDK 54 ضمن workspace مستقل. الفرع المحلي: `feature/mobile-expo`.
لا ينشئ باك إند منفصلاً أو بيانات تجريبية داخل التطبيق. مصدر البيانات والقواعد هو API الموجود في `backend/`.

## التشغيل

1. اتبع `../docs/RUN-LOCALLY.md` لتشغيل PostgreSQL والـ API وتطبيق migrations وseed.
2. من جذر المستودع: `npm install`.
3. انسخ `mobile/.env.example` إلى `mobile/.env`.
4. اضبط `EXPO_PUBLIC_API_URL` إلى عنوان الخادم الذي يستطيع الهاتف الوصول إليه، مثل `http://192.168.1.20:3000/api/v1`. عنوان localhost على الهاتف يشير للهاتف نفسه.
5. اضبط `API_PUBLIC_URL` في إعدادات الباك إند إلى عنوان يمكن للهاتف الوصول إليه أيضاً، حتى تعمل روابط الصور والوثائق.
6. من الجذر: `npm run dev:mobile`، ثم افتح المشروع بنسخة Expo Go المتوافقة مع SDK 54 أو نسخة تطوير مخصصة.

للإنتاج استخدم HTTPS. لا تضع مفاتيح سرية في متغيرات `EXPO_PUBLIC_*`.

## ما تم تنفيذه

- التسجيل وتأكيد الرمز وإعادة إرساله، الدخول واستعادة كلمة المرور وتجديد الجلسة.
- المجالات والمواضيع، فرز المنشورات، الحالات الإنسانية والفرص، الرفع والتعليقات والردود والبلاغات.
- إنشاء وتعديل المنشورات والفعاليات، الصور، الأدوار والأسئلة والمواعيد، التقديم والانسحاب.
- إدارة المتطوعين: قبول ورفض ونقل أدوار، إغلاق وإلغاء وتكرار الفعاليات.
- توثيق الفعاليات وصورها ومؤشرات أثرها، طلب وإصدار الشارات والتقييمات.
- الملف العام والخصوصية والاهتمامات، البحث عن الحسابات والمتطوعين، المتابعة والفرق والتعاون.
- طلبات النشر والتوثيق، صندوق الإشعارات، إدارة البلاغات والمحتوى والحسابات والكلمات الممنوعة.
- السيرة التطوعية وتصدير PDF ومشاركته، المظهر الداكن، روابط `wathiq://posts/123` و`wathiq://events/123` و`wathiq://users/123`.
- تبويب السيرة يعرض ساعات الفعاليات ذات الشارات المعتمدة، الشارات والفرق والأثر، ويصدر QR يحمل نسخة مختصرة مضغوطة لعرض السيرة دون اتصال. نسخة QR غير موقعة؛ تحقق أصالة كل شارة يتطلب مسح QR الشارة مع اتصال عبر `GET /api/v1/badges/verify/:id`.
- تبويب التحقق يفتح ماسح الكاميرا بخط مسح متحرك؛ كما يقبل QR السيرة دون اتصال ورموز الشارات يدوياً. بعد تسجيل الدخول يفتح التطبيق الرئيسية مباشرة، ويمكن الوصول إلى الحساب والاهتمامات من صفحة السيرة.

الصلاحيات والأهلية والمقاعد والخصوصية وإجراءات الحالة يقررها الخادم. إظهار الزر في الواجهة لا يمنح صلاحية. أنواع الاستجابات المشتركة موجودة في `packages/shared/src/models.ts` ويعيد الويب تصديرها.

التصميم مبني على `docs/design/reference-mobile.html`: العربية، Tajawal/Cairo، التدرجات البحرية، شجرة الأقسام، البطاقات المستديرة وشريط التنقل. ليست مطابقة بصرية معتمدة بعد على أجهزة فعلية.

## إشعارات الجهاز

تحتاج هاتفاً حقيقياً ونسخة تطوير أو إصداراً أصلياً، ومشروع EAS وإعدادات FCM/APNs. اضبط `EXPO_PUBLIC_EAS_PROJECT_ID`، وفعّل `PUSH_ENABLED` في الباك إند بعد إعداد الخدمة. زر التفعيل موجود في الحساب. صندوق الإشعارات الداخلي يعمل مستقلاً عن إعداد Push. لم يتم إنشاء مشروع EAS أو رفع build أو إعداد بيانات اعتماد متجر.

الجلسات الأصلية محفوظة في SecureStore. معاينة المتصفح (`npm run web -w mobile`) تستخدم ذاكرة مؤقتة فقط؛ لا تحفظ جلسة بعد إعادة تحميل الصفحة وليست بديل اختبار للهاتف.

## التحقق وحدوده

من الجذر:

```sh
npm run build:shared
npm run typecheck -w mobile
npm run test -w mobile
npm run export -w mobile
npm run lint -w web
```

نجح فحص الأنواع، و10 اختبارات لعميل API تشمل تزامن التجديد، الخروج أثناء التجديد، الاستجابات المتأخرة، وفشل الخادم والاستجابات الفارغة. نجح تصدير حزم JavaScript/Hermes لـ Android وiOS ومعاينة الويب. التصدير ليس ملف APK/IPA ولا اختبار تشغيل أصلي.

قبل الاعتماد: اختبر على Android وiOS مع API وقاعدة اختبار حقيقية، خصوصاً OTP، رفع الصور والوثائق، مشاركة PDF، أذونات الكاميرا وقراءة QR، أذونات Push، فتح الإشعار والتطبيق مغلق، لوحة المفاتيح والعربية. لم تُنفذ هذه الاختبارات على جهاز فعلي في هذه البيئة. أضيف endpoint عام لا يعيد إلا الشارات المعتمدة والظاهرة، كما أضيفت ساعات السيرة المحسوبة من مدد فعالياتها الموثقة؛ لا تتطلب هذه التغييرات migration لقاعدة البيانات.
